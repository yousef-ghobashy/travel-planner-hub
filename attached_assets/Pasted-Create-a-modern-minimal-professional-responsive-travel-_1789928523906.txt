Create a modern, minimal, professional, responsive travel planning and booking web application that allows users to search, compare, plan, and book their entire trip from one platform.

## 1. Core Concept

Build an all-in-one travel platform where the user enters:

* Departure country
* Departure city or airport
* Destination country
* Destination city
* Departure date
* Return date
* Number of travelers
* Adults
* Children
* Total trip budget
* Preferred currency
* Travel style: Budget / Standard / Luxury

The platform should then generate a personalized travel plan including:

* Flights
* Destination city
* Hotels / Motels / Apartments
* Tourist attractions
* Transportation
* Daily itinerary
* Total estimated cost
* Booking options

The user should be able to complete bookings through the website whenever the connected provider/API supports direct booking.

---

# 2. Visual Design — Minimal Modern Travel UI

The entire application must follow a **minimal, modern, calm, premium travel-tech aesthetic**.

## Design principles

* Minimalistic interface
* Clean layouts
* Plenty of whitespace
* Soft rounded cards
* Subtle shadows
* Simple navigation
* Clear visual hierarchy
* Large high-quality travel photography
* Elegant typography
* Smooth micro-interactions
* No unnecessary decorative elements
* No excessive gradients
* No visually aggressive colors
* No cluttered dashboards

## Color palette

Use calm, sophisticated colors such as:

* Off-white / warm white backgrounds
* Very light gray surfaces
* Soft beige
* Muted blue
* Dusty blue
* Soft sage green
* Charcoal / dark gray text
* One subtle accent color for primary actions

Avoid:

* Neon colors
* Extremely saturated colors
* Excessive black
* Excessive gradients
* Too many colors on the same screen

The UI should feel similar to a premium modern travel application rather than a generic booking website.

Support:

* Light mode
* Dark mode

Dark mode should remain calm and elegant rather than using pure black backgrounds.

# 27. Data Accuracy and Booking Safety

The application must clearly distinguish between:

* Real-time API data
* Cached data
* Estimated prices
* Demo data

Never present fabricated booking availability as real.

Every real-time flight/hotel/activity result should display the retrieval time where appropriate.

When an external API is unavailable:

* Display a clear error
* Use cached results when available
* Otherwise display clearly labeled demo data

Never allow a demo booking to appear as a real confirmed booking.
